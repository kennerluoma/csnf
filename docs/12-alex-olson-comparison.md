# 12 · Alex Olson: the agent's PR vs the production site

First real design through the pipeline (2026-09-17): `examples/alex-olson.fig` → [alex-olson#1](https://github.com/kennerluoma/alex-olson/pull/1), 24 min, $12.19, no renders. Compared against the shipped site (`examples/alex-olson-site`, Next.js pages router, static export on Netlify, Sanity v3, 40 commits 2023-05 → 2026-05).

## What the agent got right

- The split-screen shell (black left, white right), the nav in `mix-blend-difference` across the seam, active-item underline, comma separators. Production does exactly this.
- Reusing the content types (artwork, exhibition, page) instead of blocks; production has the same shape: four document types + pages.
- Paintings as thumbnail grid + viewer, exhibitions as year/title list + detail, about as rich text with links.
- Everything the file said nothing about and the plan flagged: the trial font, the nav item with no screen, the duplicate frame.

## Design drift

The file is older than the site. The rotated captions, the lightbox and the mobile menu were all decided after the Figma, in code, with the client. So the comparison is partly "what the design leaves out" and partly "what got designed later in the browser". Both argue for the same thing: the pipeline's rebuild loop (branch → PR → preview) is where those decisions will keep happening, and the prompt should expect designs to be incomplete about interaction and mobile.

## What changed because of this

- Extractor: pages named Mobile are read as mobile viewports alongside the main page.
- Prompt (`translate.md`): rules for mobile, splash frames, states as interactions, captions, fluid type, list ordering.
- Template: `artwork.collection`, `artwork.caption`, `artwork.date`; `imageWithAlt.caption`; `exhibition.pressRelease` + label; `Image` blur-up, `sizes` and quality.
